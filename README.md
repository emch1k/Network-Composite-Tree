# Network Composite Tree

Учебный проект на Python, демонстрирующий паттерн проектирования **Composite** («компоновщик»). Моделирует сеть, состоящую из компьютеров, у каждого из которых есть IP-адреса и аппаратные компоненты (CPU, память, диски с разделами).

## Идея

Все элементы дерева — от одиночного `CPU` до целой `Network` — реализуют общий интерфейс `Printable`. Благодаря этому:

- любой узел, простой или составной, можно распечатать одинаковым способом;
- вывод дерева происходит рекурсивно: родитель просто просит каждого потомка отрисовать себя, передавая нужный отступ (`prefix`) и информацию о том, последний ли это элемент в списке;
- любой узел можно глубоко клонировать (`clone()`) — включая всё его содержимое.

## Структура классов

| Класс | Роль | Тип узла |
|---|---|---|
| `Printable` | Абстрактный интерфейс: `print_me()` + `clone()` | — |
| `Address` | IP-адрес | Лист |
| `Partition` | Раздел диска | Лист |
| `CPU` | Процессор (ядра, частота) | Лист |
| `Memory` | Оперативная память | Лист |
| `Disk` | Диск (SSD/HDD) с разделами | Составной |
| `Computer` | Компьютер: адреса + компоненты | Составной |
| `Network` | Сеть: список компьютеров | Составной |
| `Component` | Общий предок аппаратных компонентов | Абстрактный |
| `BasicCollection` | Базовая коллекция с `add`/`find`/`clone` | Вспомогательный |

## Пример вывода

```
Network: MISIS network
+-Host: server1.misis.ru
| +-192.168.1.1
| +-CPU, 4 cores @ 2500MHz
| \-Memory, 16000 MiB
\-Host: server2.misis.ru
  +-10.0.0.1
  +-CPU, 8 cores @ 3200MHz
  \-HDD, 2000 GiB
    +-[0]: 500 GiB, system
    \-[1]: 1500 GiB, data
```

## Запуск

```bash
python network.py
```

## Известные ограничения

- `Partition` объявлен как отдельный класс `Printable`, но фактически не используется — разделы диска хранятся в `Disk` как обычные кортежи `(size, name)`.
- `BasicCollection` реализует общую логику коллекции (`add`, `find`, `clone`), но `Computer` и `Network` её не наследуют, хотя логически могли бы, чтобы не дублировать код.
